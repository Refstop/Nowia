호스트 개별 분석·테스트와 두 failure probe는 `79fb88c223bb42bce1ec153b977f07aabb8400d4` HEAD에 당시 미커밋 도구를 사용했다. 이후 구현을 `c46c32f`로 고정했고 새 컨테이너의 정상 전체 검증은 그 commit을 실행했다. probe 결과 문자열의 `propagated to CI`는 코드 메시지이며 실제 GitHub 실패 job 확인을 의미하지 않는다.

원격 Git 인증의 다른 계정은 dry-run push에서 403이었다. 사용자가 학교 계정 Refstop을 선택한 후 저장소 관리자·push 역할을 읽기로 확인했지만, 그 연결 앱의 브랜치 생성도 **HTTP 403 `Resource not accessible by integration`**으로 거절됐다. [접근 결과](fnd04-05/remote/access-result.json)에 기록했다. 원격 ref 변경·PR·merge는 없다. 권한 변경 확인 없이 다른 계정이나 전송 방식으로 재시도하지 않았다.

GitHub 정상 workflow, evidence/APK 업로드·다운로드, 의도한 실패 job은 모두 **NOT_RUN**이다. 실제 원격 실행 전 FND-05를 VERIFIED로 표시하지 않는다.

## 증거 보존과 후속 상태

원 기록 `/workspace/fnd04-repro`에서 로그·JSON·텍스트를 선별해 [fnd04-05](fnd04-05/SHA256SUMS.json)에 보존했다. 다운로드한 SDK/JDK archive, APK, CA 파일, debug key는 Git 증거에 넣지 않았다. 중복 집계 로그를 제외하고 stage별 원 로그의 bytes를 유지했다. 따라서 원 로그의 trailing whitespace는 수정하지 않는다. SHA256SUMS는 자기 자신을 제외한 이 디렉터리의 모든 보존 파일을 검증한다.

FND-04는 **컨테이너 재현 PASS / publish·새 task NOT_RUN**, FND-05는 **로컬 준비·검증 완료 / 원격 권한 BLOCKED**, APP-01은 **WAITING_DEVICE**다. G0·G1은 NOT_ACCEPTED를 유지한다. 다음은 연결 권한 해결 후 원격 CI·artifact 검증, 별도 Cloud 환경 재현과 실제 태블릿 시험이다.
