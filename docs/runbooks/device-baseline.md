# APP-01 Galaxy Tab S7 태블릿 시험 안내

상태: **WAITING_DEVICE / 모든 실기기 항목 NOT_RUN**. 2026-10-13 KST 기준 시험 준비 문서이며 실행 증거가 아니다. 개발자는 FND-04·FND-05를 진행할 수 있고, 사용자는 준비되는 때에 아래 시험을 수행하면 된다. 실제 S Pen·한글·저장 시험 전 G1은 미통과다.

## 1. 설치 경로 선택

**기존 Butterfly가 없다면:** 아래 APK를 태블릿으로 옮겨 열고 Android 설치 안내를 따른다. 설치 출처 권한을 요구하면 파일을 여는 앱에만 허용한다. 설치 후 앱 이름은 **Butterfly**다. Nowia 기능은 아직 없다. 설치 오류가 나면 오류 문구와 기기 모델·Android 버전을 기록한다.

**기존 Butterfly가 있다면:** 앱과 노트를 그대로 두고 이번 APK 설치는 보류한다. 원본 앱과 같은 식별자에 debug 서명을 사용하므로 업데이트가 충돌할 수 있다. 기존 앱 삭제·데이터 지우기·다운그레이드로 해결하지 않는다. 기존 앱의 버전·설치 출처·노트 유무를 결과 양식에 적어 전달하면 개발자가 공존 가능한 후속 시험 빌드 경로를 검토한다. 이 원본 APK에 별도 식별자를 적용한 상태는 아니다.

기존 노트를 백업하려면 설치된 버전의 내보내기 기능으로 앱 밖의 파일 위치에 사본을 보관한다. v2.6.0 소스에서 확인한 경로는 **설정 → 데이터 → 모든 파일 내보내기**이며 파일·팩·템플릿을 ZIP으로 내보낸다. 개별 노트는 문서 메뉴의 **내보내기 → 패키지 파일**로 `.bfly` 사본을 만든다. 기존 앱 버전의 메뉴는 다를 수 있다. 파일 생성만으로 복원 성공을 가정하지 않으며, 백업 여부와 관계없이 기존 앱 삭제는 이 시험에 포함하지 않는다. 개인 노트나 백업은 채팅·공개 저장소에 올리지 않는다.

## 2. 새 시험 노트로 15~20분 확인

개인 자료 대신 `APP01-날짜`라는 새 로컬 노트를 만든다. 원격 동기화·공동 작업·외부 OCR/AI는 연결하지 않는다. 외부 OCR/AI 기본 OFF는 프로젝트 정책이며 원본 앱에 Nowia의 전송 차단 기능이 구현되었다는 뜻은 아니다. 모델 코드, Android/One UI, 주사율, 키보드 앱 이름을 [결과 양식](device-results-template.md)에 적는다.

| 순서 | 직접 할 일 | 확인·기록할 점 | 현재 |
|---|---|---|---|
| 1 | S Pen으로 한글·영어·수식·도식을 10분 정도 쓴다. 작은 점·곡선·빠른 긴 획도 그린다. | 획 누락·끊김·원치 않는 점, 펜을 따라오는 체감 지연. 지연은 `불편 없음 / 거슬림 / 쓰기 어려움`으로 기록한다. | NOT_RUN |
| 2 | 같은 펜 도구에서 약하게/강하게 눌러 선을 긋고, 지우개로 지운 뒤 실행 취소·다시 실행한다. | 굵기 변화·지우기·복구 결과. 필압 설정과 S Pen 버튼 동작도 기록하며, 필압 미반영 시 설정 상태를 먼저 남긴다. | NOT_RUN |
| 3 | 손바닥을 먼저 댄 경우와 펜을 먼저 댄 경우를 각각 시도한다. 확대·축소·화면 이동 뒤 다시 쓴다. | 손바닥 자국, 의도하지 않은 이동, 필기 중단 여부. 남은 자국이 저장 후에도 보이는지 확인한다. | NOT_RUN |
| 4 | 텍스트 도구에서 `한글 입력 시험: 값, 읽기, 괜찮아요. ABC 123`을 입력한다. 중간 글자 수정·받침 삭제·커서 이동·줄바꿈·붙여넣기·화면 회전을 한다. | 글자 유실·중복, 한글 조합 분리, 커서 튐. 사용한 키보드와 문제가 생긴 정확한 문구를 적는다. | NOT_RUN |
| 5 | 마지막에 `저장 확인 1`과 별 모양을 추가해 저장한다. 앱 안에서 홈으로 나간 뒤 Android 최근 앱 화면에서 Butterfly를 닫고 다시 실행해 같은 노트를 연다. | 마지막 문구·별·기존 획·텍스트·페이지가 모두 같은지 확인한다. 앱을 닫기 전에 저장 상태를 확인한다. | NOT_RUN |
| 6 | 아래 절차로 `.bfly` 사본을 내보내고 별도 시험 폴더에 가져온다. | 원본을 남긴 채 복원 사본의 획·텍스트·페이지를 비교한다. PDF/이미지만 내보내는 것은 원본 복원 시험이 아니다. | NOT_RUN |
| 7 | 복원한 **시험 사본**에 `저장 확인 2`를 추가하고 저장 완료 후 Android 앱 정보에서 Butterfly를 강제 종료한다. 다시 실행해 사본을 연다. | 마지막 저장 상태가 보존되는지. `저장 중` 상태에서 강제 종료하지 않는다. `데이터 삭제`는 누르지 않는다. | NOT_RUN |
| 8 | 비행기 모드에서 시험 사본에 한 줄 더 쓰고 저장·재실행한다. | 네트워크 없이 필기와 저장 복원이 되는지. | NOT_RUN |

저장 버튼이 보이면 `Saved` 상태를 확인한다(`Saving...`, `Unsaved`는 저장 완료가 아님). 자동 저장 등 설정에 따라 버튼이 보이지 않을 수 있으므로 앱의 홈으로 이동한 뒤 노트를 다시 열어 마지막 변경을 먼저 확인한다. 저장 여부를 확인할 수 없다면 강제 종료 시험은 `NOT_RUN`으로 남긴다.

`.bfly` 복원 절차: 시험 노트의 메뉴에서 **내보내기 → 패키지 파일**을 선택해 로컬 파일로 저장한다. 앱의 파일 목록에서 원본과 구별되는 시험 폴더를 열고 **가져오기**로 그 파일을 선택한다. 생성된 사본을 열어 비교한다. 메뉴 경로는 v2.6.0 소스로 확인했으며, 실제 Android 파일 선택 화면과 기기 동작은 아직 검증하지 않았다.

## 3. 결과 전달

[결과 양식](device-results-template.md)을 복사해서 채팅으로 보내면 된다. 우선 **설치 / S Pen / 한글 / 정상 재실행 / 강제 종료 후 복원 / .bfly 복원**의 통과 여부와 불편했던 점만 전달해도 된다. 실패는 발생 순서·예상/실제·재현 빈도를 적고, 필요할 때 합성 노트만 보이는 화면이나 영상을 붙인다. 실제 노트가 없어지거나 손상되면 해당 문서 시험을 멈추고 직전 원본과 현재 사본을 보존한다.

공식 앱을 이미 사용할 수 있으면 같은 합성 내용으로 비교하고 공식 버전·출처·설정 차이를 적는다. 비교 때문에 기존 앱을 교체하지 않는다. 공식 앱만 시험한 결과는 자체 APK 결과와 구분한다. 비교하지 못한 항목은 `NOT_RUN`이다.

개발자는 전달받은 사실을 검토해 `docs/evidence/APP-01.md`에 기록하고 `일상 필기 가능 / 조건부 가능 / 기반 부적합`을 판정한다. 현재는 해당 판정과 G1 모두 대기다. debug APK의 체감 결과로 출시 성능이나 물리적 입력 지연 수치를 확정하지 않는다. 저장 중 중단·용량 부족 등 전체 내구성 시험은 CORE-05/QA-01에서 별도로 수행하되, 이번에 발견한 데이터 손실은 즉시 추적한다.
